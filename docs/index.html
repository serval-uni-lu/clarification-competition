Competition format

Rules & tracks

Keep the algorithm small, reproducible, and focused on the central problem: recognizing when a requirement needs clarification.

01
Single-turn track

One chance to clarify

The system may make at most one clarification turn before returning its implementation. Exact organizer constraints can be updated in data/competition.json.

02
Multi-turn track

Clarify iteratively

The system may ask multiple targeted clarification questions within the organizer-defined turn budget. Exact budget: TBA.

1

Submit one algorithm file

Implement a class inheriting from ClarificationAlgorithmBase. Competition submissions live in clarify/algorithms/<name>.py.

2

Use the provided environment

Your algorithm interacts through the SDK, including env.llm(...), env.ask_human(...), and the provided execution interface.

3

Submit through a pull request

Fork the repository, add your algorithm, include the required submission header and team metadata, then open a pull request.

4

Public first, private last

Develop against the training split and public validation set. Private-test scores are held back and revealed only at final evaluation.

Benchmark. Tasks are derived from MBPP and HumanEval and include variants with ambiguous, incomplete, or contradictory specifications. The repository currently documents 7,961 training examples and 770 validation examples.
Evaluation

What gets measured

The main score rewards correct implementations with fewer clarification turns; additional metrics make the trade-offs visible.

TDS

Turn-discounted success

Primary metric. Rewards passing implementations while discounting solutions that need more clarification turns.

P@1

Pass@1

Raw percentage of generated implementations that pass the developer tests.

nDCG

Clarification quality

Rewards consistently useful clarification questions across turns, as judged against the published quality criteria.

CR

Clarification rate

Percentage of tasks for which the system asks at least one clarification question.

OA

Over-asking rate

How often the system asks a question even though the task is sufficiently specified. Lower is better.

$

Average cost

Average LLM/API cost per task, shown alongside quality metrics rather than folded into the primary score.

Get started

From idea to leaderboard

Participation follows the repository workflow, so teams can prototype locally and submit the final algorithm through GitHub.

Open competition repository ↗
  1. 01
    Fork & install

    Fork the repository, install the SDK with uv, and configure your model API key.

  2. 02
    Implement

    Add a single clarification algorithm that inherits from ClarificationAlgorithmBase.

  3. 03
    Evaluate

    Run response generation and evaluation on the available train/validation splits.

  4. 04
    Submit

    Open a pull request with the required team and licensing header. Approved public results can then be added to the CSV leaderboard.
